When the landing date moves, the sunlight and the radio link move with it.

At the Moon's south pole the Sun and the Earth both stay within a few degrees of the horizon. A new date, or a site a little closer to the pole, can cost a lander its power or its link to Earth for days.

The data to check this is public, in JPL Horizons, Quickmap and Moon Trek. The challenge statement names the gap: judging each site and date means moving between several interfaces and reading raw numbers.

A planner with two options has to run that twice and work out the difference by hand.

Every number is tested against NASA JPL Horizons.

NASA data in the tool. JPL Horizons for the reference tables. Lunar Reconnaissance Orbiter colour mosaic and laser altimeter heights for the 3D Moon. Site coordinates from NASA, LROC and NSSDCA pages, each linked on the page.

What it leaves out. The horizon is flat. Hills, crater rims and lander tilt are not modelled, and the page says so beside the numbers.

One page, no server, open source.

How it is built

Plain HTML, CSS and JavaScript. It opens from a file with no network and no account. Astronomy Engine (MIT) gives the positions. The 3D Moon is our own WebGL code with no library behind it.

Use of AI

The idea is the team's. The code, the tests and these slides were written with Claude Code under the team's direction. Every file is labelled and SI_USE.md logs each session. Nothing here is an AI-generated image.
